# TONARI

この先を、ともにする人と。結婚相談所に近い、審査制の婚活アプリです。

## 起動

Node.js 20.9以上・pnpmを使用します。

```sh
pnpm install
cp .env.example .env.local
pnpm dev
```

http://localhost:3000 で表示します。確認後は Ctrl+C で停止してください。本番モードは `pnpm build` → `pnpm start`。

`.env.local` の `TONARI_ADMIN_PASSWORD` に8文字以上のパスワードを設定すると `/staff` から審査できます。未設定では運営ログインできません。

## 体験の流れ

1. `/register` で登録し、入会申請を送信。
2. `/staff` で運営が申請を確認し、承認・差し戻し・否認。
3. 承認後、4ステップで希望条件と大切にしたい価値観を入力。
4. 双方の必須条件に合う複数名を、紹介理由・話し合いたい点とともに紹介。写真は非公開。
5. 「お話ししたい」の希望を送り、相手が承諾すると成立。ここで初めて写真を公開。
6. 成立中は新しい紹介・別の相手への希望を停止。面談希望を運営へ送信可能。
7. 明示的なお断りで終了。相手へのアプリ内通知と双方の履歴を記録してから、次の紹介を解放。終了した相手は再紹介しません。

女性会員はローズ、男性会員はセージの配色です。会員画面には20秒ごと・再フォーカス時の更新があります。終了後、相手の写真・詳細の再取得はサーバー側で拒否します。

## 架空会員で確認する

`.env.local` に以下を設定してから起動します。

```dotenv
TONARI_DEMO_ENABLED=true
TONARI_DEMO_PASSWORD=自分で決めた8文字以上のパスワード
```

承認済みの架空会員12名が用意されます。ログイン画面の「DEMO MEMBERS」から会員を選ぶと、パスワードなしでそのまま体験できます。会員画面のサイドバーからは別のデモ会員へいつでも切り替えられます。メールアドレス（`member-m1@example.test` ～ `member-m12@example.test`）と共通パスワードでの通常ログインも可能です。

`member-m1`（美咲）と `member-m7`（拓海）は、ログイン時点でご縁が成立しています。相手の写真が公開された状態と、面談希望の送信・ご縁の終了を確認できます。紹介の流れを最初から試すには `member-m2` ～ `member-m6` / `member-m8` ～ `member-m12` を使ってください。それ以外の会員は、初期状態では紹介未取得です。

デモ会員の切り替えはサーバーのセッションではなく Cookie で保持するため、サーバーレス環境でインスタンスが変わっても追い出されません。デモを無効にすると新規登録からの導線のみになります。実在する会員はいません。写真はAI生成画像です。

## 構成とデータ

Next.js App Router / TypeScript / React / Zod。認証・審査・条件判定・紹介・成立・終了通知はサーバー側で処理します。

- パスワードはソルト付きscryptでハッシュ化。ランダムなセッションIDをHttpOnly / SameSite=Lax Cookieで管理（本番ではSecure）。会員セッション24時間、運営セッション1時間。
- 会員情報は認可後の必要項目だけを返却。写真は `private/portraits` またはメモリに保存し、認可付き `/api/portraits/[id]` で配信。公開URL・静的会員一覧はありません。
- 本人の写真と、成立中の相手の写真だけ取得可能。写真アップロードは形式・容量・画素数を検証し、メタデータを除去します。
- 希望の承諾と終了は一つの処理で状態更新し、同時成立や通知だけ欠ける終了を防ぎます。
- 通報・ブロック・退会・運営による制限中のご縁の終了にも対応。

すべて単一サーバープロセスのインメモリです。再起動でアカウント、写真アップロード、審査、通知、履歴を失います。セッションの期限切れだけでは関係は終了しません。複数プロセス・サーバーレスの共有状態は未対応です。

Vercel などのサーバーレス環境では、リクエストごとに別インスタンスになることがあるため、登録したアカウントや操作の結果は保持されません。デモ会員の切り替えは Cookie で保持するため継続しますが、通常ログインは再読み込みでログアウトされる場合があります。安定した体験にはローカル起動を使ってください。デモ会員の写真は `outputFileTracingIncludes` で関数に同梱されますが、アップロードした写真は永続化されません。

運営審査の操作は実装していますが、公的書類による本人・独身確認、メール確認・配送、パスワード再発行、担当者別の運営認証、外部への面談予約は未接続です。現段階で本人確認書類は収集しません。正式運用時には永続保存とこれらの運用基盤を接続してください。

## 開発・検証

| コマンド | 内容 |
| --- | --- |
| `pnpm typecheck` | 型チェック |
| `pnpm lint` / `pnpm format` | Biome検査 / 整形 |
| `pnpm knip` | 未使用コード検出 |
| `pnpm test` | 認証・状態遷移・写真アクセスのVitestテスト |
| `pnpm build` | 本番ビルド |
| `pnpm e2e` | 公開範囲・未認証リダイレクトのPlaywrightテスト（ビルドとChromiumが必要） |

仕様は `docs/consultation-based-experience.md`、画像の生成記録は `docs/portrait-sources` にあります。
